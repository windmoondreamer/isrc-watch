# isrc-watch

노션 「인생 리바이벌 2026」 아침 루틴 자동화.
두 워크플로가 돌고, 클로드 클라우드 루틴은 브리핑만 남았다.

| 시각 (KST) | 주체 | 하는 일 |
|---|---|---|
| 07:00 | **`daily.yml`** | 스케줄 리셋 · D-Day · 마감/접수시작 콜아웃 · 상태 동기화 · 수면 기록 · 주간회고·신체측정 행 |
| 07:20 | **`watch.yml`** | 교육·공모전 소스 12곳 파싱 → 신규 공고 DB 자동 등록 |
| 07:40 | 클로드 루틴 (클라우드) | 반도체 소식 브리핑 · 세계 경제 브리핑 (LLM 필요) |

판단이 필요 없는 일은 전부 코드로 내려왔다. 클로드는 "뉴스 읽고 내 말로 요약"만 한다.

## 왜 GitHub Actions인가

클로드 클라우드 루틴(매일 07:06 KST)은 아웃바운드가 프록시로 전면 차단돼 있다 —
구글조차 CONNECT 403. 그래서 교육 사이트를 직접 못 읽고 WebSearch로만 교차확인하다가,
검색엔진에 색인 안 된 공고를 놓쳤다 (2026-07 서울대 연합교육 실습 며칠 누락).

GitHub Actions 러너는 네트워크 제약이 없으므로 원본 사이트를 직접 파싱한다.
클로드 루틴은 그대로 두고(스케줄 리셋·D-Day·마감 콜아웃·브리핑 담당),
여기서는 **"공고 누락 방지"만** 책임진다.

## 왜 나눴나

클로드 루틴은 무인 실행이라 사용자에게 물어볼 수 없고, LLM이라 매일 조금씩 다르게 행동한다.
날짜 계산·체크박스 리셋·D-Day 같은 결정론적 작업은 코드가 훨씬 안정적이고 무료다.
반대로 뉴스 요약은 코드로 못 한다 — 그래서 딱 그것만 남겼다.

## 소스

수집 대상은 **신청 가능한 공고**와 **새 프로그램의 단서** 둘 다다. 후자는 마감일이
없으므로 발견까지만 하고, 모집 여부 확인은 사람에게 넘긴다.

| 소스 | 방식 | 목적지 DB |
|---|---|---|
| 서울대 ISRC 교육시스템 | 일정 JSON (`/edu/school/info/state/json`) | 교육·강의 |
| IDEC 단기교육 | 수강신청 목록 HTML 테이블 | 교육·강의 |
| KSIA 인프라 | 목록 + 상세 HTML (비재직자 과정) | 교육·강의 |
| KANC 한국나노기술원 | 교육 게시판 HTML | 교육·강의 |
| NNFC 나노종합기술원 | 교육 목록 JSON (`list_json.do`) | 교육·강의 |
| 대학 게시판 (건국대 등) | 표준 CMS(`artclList.do`) 공통 파서 | 교육·강의 |
| 성균관대 전자전기 취업공지 | `notice_job.do` 블록 파싱 | 교육·강의 |
| 성균관대 반도체시스템공학과 | 자체 게시판(oxbbs, EUC-KR) | 교육·강의 |
| SK하이닉스 뉴스룸 | 워드프레스 REST API 검색 | 교육·강의 (발견용) |
| SK하이닉스 반도체 커리큘럼 | 공식 사이트(Oopy) 회차 문구 감시 | 교육·강의 (발견용) |
| 산업통상부 보도자료 | 목록 HTML + 반도체·인력 동시 필터 | 교육·강의 (발견용) |
| 위비티 (과학/공학) | 목록 HTML + 반도체 키워드 필터 | 공모전·경진대회 |

검색은 프로그램명을 고정해 찾지 않는다. `반도체 교육`·`인재양성`·`계약학과`·`아카데미`·
`부트캠프`·`채용연계` 같은 **유형 키워드**로 훑어야 이름을 모르는 새 프로그램이 걸린다.

제외한 소스:
- **삼성전자 뉴스룸** — Akamai가 `wp-json`과 검색을 403으로 막는다 (메인만 열림).
- **과학기술정보통신부** — 2026-09-02 확인 시점에 사이트 시스템 점검 중이라 미검증.
- **고려대·연세대 반도체학과** — 본문이 JS 렌더라 HTML에 목록이 없다.
- **한국반도체아카데미(KSA)** — SPA라 API가 은닉돼 있고 몇 주째 신규 0건. 클로드 루틴의 WebSearch가 커버.
- **SEMI** — 봇 차단(403) + "6학기 이상" 요건이라 현재 자격 미달.
- **링커리어** — GraphQL 클라이언트 페칭. 위비티가 공모전을 커버.
- **SETEC(한기대)** — EUC-KR + 재직자 훈련위탁 위주.

## 유형 분류

교육 항목은 등록할 때 메모 앞머리에 유형 태그가 붙고, 실행 요약도 이 축으로 묶인다.
기존 `분야`(공정/디지털설계/아날로그설계)는 **내용** 축이고, 이건 **기회의 형태** 축이라
노션 스키마를 건드리지 않고 메모로만 표시한다.

1. 대학 계약학과·학위과정
2. 정부 지원 프로그램
3. 부트캠프·단기 아카데미
4. 기업 주관 교육과정
5. 일반 교육과정 (위 어디에도 안 걸리면)

앞 규칙이 이긴다 — 'SK하이닉스 반도체 계약학과'는 기업이 아니라 계약학과로 분류된다.

## 발견 항목의 자동 만료

뉴스 기사·게시판 글에는 신청마감이 없다. 그대로 두면 `cleanup_expired`가 손대지 못해
(날짜를 모르면 보존이 원칙) 노션에 영구히 쌓인다. 그래서 메모에 `[EXPIRE:YYYY-MM-DD]`를
심고 정리 단계가 그것도 만료 사유로 본다. 기본 유효기간은 게시일 기준 90~120일.

ISRC의 `(일반)` 과정은 재직자 트랙이라 자동 제외한다 (같은 교육의 `(학생)` 트랙이 따로 열림).

## 중복 방지

`주요 일정` 텍스트에 `[SRC:<소스>:<id>]` 마커를 심고, 그걸로 판정한다.
회차명이 바뀌어도 중복 등록되지 않는다.

마커가 없는 기존 행(사람이나 클로드가 넣은 것)은 **제목 포함 관계**로 한 번 더 거른다 —
정규화(공백·괄호·기호 제거)한 제목이 서로 포함되면 같은 강좌로 본다.

## 자동 분류

- 교육 `분야`: 제목 키워드로 공정 / 아날로그설계 / 디지털설계 / 공통 추론
- 공모전 `방식`: AI·데이터 / 설계 / 복합 추론
- `상태`: 소스의 접수 상태 → 신청중 / 예정
- `신청마감`·`접수마감`: 소스의 접수종료일 (KST)

## 스케줄

매일 22:20 UTC = **07:20 KST**. 클로드 아침 루틴(07:06 KST) 직후라,
루틴이 갱신한 DB 위에 신규 건만 얹는 순서가 된다.

수동 실행: Actions 탭 → "반도체 교육 공고 감시" → Run workflow

## 로컬 테스트

```bash
export NOTION_TOKEN='ntn_...'
export NOTION_EDU_DB='3244fcb7249c4098aa5a7f81a572c8cb'
export NOTION_CONTEST_DB='a9e6fc4e940a43628a018bc6220c91d5'
python3 scripts/watch.py
```

소스 하나가 죽어도 나머지는 계속 돈다. 전부 죽으면 워크플로가 실패로 표시된다.

노션 토큰 없이 파서만 확인하려면:

```bash
python3 scripts/watch.py --collect-only
```

수집 결과를 유형별로 출력하고 노션은 읽지도 쓰지도 않는다. 새 소스를 붙일 때
0건이 '진짜 0건'인지 '조용한 실패'인지 여기서 먼저 가른다.
